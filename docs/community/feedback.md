## 为什么需要您的反馈？

段言还是一个年轻的语言，您的每一条反馈都直接影响着它的发展方向。通过反馈，我们可以：

- **发现 Bug**：及时修复问题，提升稳定性

- **改进体验**：优化文档、错误信息和用户界面
- **建设社区**：让用户参与到语言的设计和演进中来

## 反馈类型

### 🐛 Bug 报告

如果您在使用段言时遇到了错误或异常行为，请提交 Bug 报告。

**提交方式**：[GitHub Issues - Bug 报告](https://github.com/skywalk163/duan/issues/new?template=bug_report.md)

**好的 Bug 报告包含**：

1. **清晰的问题描述**：用一句话说明发生了什么问题
2. **完整的复现步骤**：从创建文件到运行命令的完整过程
3. **最小可复现代码**：尽可能精简的代码片段
4. **环境信息**：操作系统、Python 版本、段言版本
5. **完整的错误信息**：复制完整的错误输出，不要截取片段

**示例**：

```markdown
## 描述
使用 `duan run` 运行包含中文注释的文件时，词法分析器报错。

## 复现步骤
1. 创建文件 test.duan，内容为：
   ```段言
   # 这是一条中文注释
   打印 "你好"
   ```
2. 运行：`duan run test.duan`
3. 看到错误：
   ```
   SyntaxError: 第 1 行：意外的字符 '#'
   ```

## 环境信息
- 操作系统：Windows 11
- Python 版本：3.12.0
- 段言版本：v6.0.0
- 安装方式：pip install duan
```

### 💡 功能建议

如果您有改进段言的想法或建议，请提交功能建议。

**提交方式**：[GitHub Issues - 功能请求](https://github.com/skywalk163/duan/issues/new?template=feature_request.md)

**好的功能建议包含**：

1. **问题的背景**：说明当前遇到了什么不便或限制
2. **具体的解决方案**：描述你期望的功能是如何工作的
3. **使用示例**：展示该功能在实际代码中的用法
4. **替代方案**：你还考虑过哪些其他方案
5. **适用场景**：该功能在什么场景下最有用

**示例**：

```markdown
## 问题描述
当需要处理大量 JSON 数据时，当前 JSON 解析器不支持流式解析，
导致大文件会占用大量内存。

## 建议方案
为 JSON 模块添加流式解析支持，允许逐行解析大型 JSON 文件。

```段言
设 解析器 为 创建JSON流式解析器()
设 文件 为 打开文件("large.json", "r")
当 文件.未结束():
    设 对象 为 解析器.解析下一项()
    如果 对象 不等于 无:
        处理(对象)
关闭文件(文件)
```

## 替代方案
- 使用外部工具预处理 JSON 文件
- 分块读取后手动解析

## 适用场景
- 大规模数据处理
- 日志文件分析
- 数据导入导出
```

### 📖 文档反馈

如果您发现文档中的错误、遗漏或不清楚的地方，欢迎反馈。

**提交方式**：
- 直接在文档页面的 [GitHub 源码](https://github.com/skywalk163/duan/tree/main/docs) 上提交 PR
- 在 [GitHub Discussions](https://github.com/skywalk163/duan/discussions) 中发起讨论
- 提交 [Issue](https://github.com/skywalk163/duan/issues/new) 并标注为 `docs`

**好的文档反馈包含**：

1. **文档位置**：文档的路径或 URL
2. **问题描述**：是错误、遗漏还是不清楚？
3. **建议的修改**：你期望的正确内容是什么？
4. **参考信息**：相关的代码示例或其他参考资料

### 💬 一般反馈

如果您有其他想法、意见或建议，可以通过以下方式分享：

- **GitHub Discussions**：在[一般讨论](https://github.com/skywalk163/duan/discussions/categories/general)分类中发帖
- **功能建议**：在[功能建议](https://github.com/skywalk163/duan/discussions/categories/ideas)分类中提出

## 反馈处理流程

我们按照以下流程处理每一份反馈：

```
提交反馈 → 分类 → 确认 → 评估 → 排期 → 实施 → 发布
```

### 各阶段说明

| 阶段 | 说明 | 预计时间 |
|------|------|----------|
| **提交** | 用户通过 Issue 或 Discussion 提交反馈 | - |
| **分类** | 维护者将反馈分类（Bug/功能/文档/其他） | 1-2 个工作日 |
| **确认** | 确认 Bug 可复现或功能建议合理 | 1-3 个工作日 |
| **评估** | 评估影响范围、实现难度和优先级 | 1-2 周 |
| **排期** | 纳入开发计划，分配里程碑 | 视优先级而定 |
| **实施** | 开发、测试、代码审查 | 视复杂度而定 |
| **发布** | 随下一个版本发布 | 随版本节奏 |

### 优先级说明

| 优先级 | 标签 | 说明 | 响应时间 |
|--------|------|------|----------|
| 🔴 **紧急** | `critical` | 严重 Bug，影响核心功能 | 24 小时内 |
| 🟠 **高** | `high` | 重要功能或影响较大的 Bug | 3 天内 |
| 🟡 **中** | `medium` | 常规功能或易修复的 Bug | 1 周内 |
| 🟢 **低** | `low` | 小改进或非关键问题 | 2 周内 |

## 反馈质量指南

### 好的反馈示例

```markdown
## 问题描述
在使用 `duan compile` 命令编译包含类型注解的文件时，LLVM 后端
报错 "TypeError: unsupported type"。这个问题在 v6.0.0 中仍然存在。

## 复现步骤
1. 创建文件 test.duan：
   ```段言
   段落 加法 接收 甲: 整数, 乙: 整数 -> 整数:
       返回 甲 + 乙
   
   设 结果 为 加法(3, 5)
   打印 结果
   ```
2. 运行：`duan compile test.duan --backend llvm-typed`
3. 错误信息：
   ```
   TypeError: unsupported type: 整数
   File "test.duan", line 1, in 加法
   ```

## 环境信息
- 操作系统：macOS 14.5
- Python 版本：3.12.3
- 段言版本：v6.0.0
- 安装方式：pip install duan

## 期望行为
应该能成功编译并生成可执行文件。
```

### 不够好的反馈示例

```markdown
段言有问题，JSON 解析不了，快点修一下。
```

**问题**：信息不完整，无法定位问题。

### 如何改进

1. 提供完整的错误信息
2. 提供可复现的代码
3. 说明你的环境配置
4. 描述你期望的行为
