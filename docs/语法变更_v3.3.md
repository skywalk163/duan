# 段言语法变更 v3.3

**版本**：v3.3
**日期**：2026-08-03
**状态**：正式版
**基于**：v3.2 统一语法规范

---

## 概述

本次变更围绕两个核心问题展开：
1. **代码转换时的语法不足** — Python 有而段言无的语法结构如何处理
2. **初学者友好度** — 选词是否繁琐、是否容易上手

核心思路：段言是独立的中文语言，Python/C 代码作为"外语引用"嵌入，边界清晰，不做中文拉丁化。

---

## 1. 嵌入块语法（新增）

### 1.1 设计理念

段言不需要为每种 Python 语法找中文对应。就像中文文本中可以嵌入数学公式和英文缩写一样，段言允许直接嵌入 Python/C 代码块。

嵌入块是"外语引用"，不改变段言自身语法。

### 1.2 语法格式

```
嵌入 Python:
    <原始 Python 代码>
结束嵌入

嵌入 C:
    <原始 C 代码>
结束嵌入
```

### 1.3 示例

**Python 嵌入块**：
```
设 甲 为 10。
嵌入 Python:
    甲 = 甲 * 2
    result = [x**2 for x in range(甲)]
    print(f"结果: {result}")
结束嵌入
打印 甲。
```

Python 嵌入块直接共享段言变量作用域，无需显式传递。

**C 嵌入块**：
```
嵌入 C:
    int add(int a, int b) {
        return a + b;
    }
结束嵌入
```

C 嵌入块通过 ctypes 编译执行，生成的共享库自动加载。

### 1.4 实现细节

- **Lexer 层**：在词法分析阶段检测 `嵌入` 关键词，捕获到 `结束嵌入` 的原始文本，作为单个 `EMBED_BLOCK` token 输出，避免段言分词器破坏嵌入代码
- **Parser 层**：`EmbedBlock` AST 节点包含 `language`（语言名）和 `code`（原始代码）
- **Code Generator**：Python 嵌入块直接输出原始代码（`textwrap.dedent` 处理缩进）；C 嵌入块生成 ctypes 编译加载代码

### 1.5 解决的语法缺口

以下 Python 语法不再需要在段言中寻找对应，直接嵌入即可：
- 装饰器（`@staticmethod`、`@property` 等）
- async/await
- lambda 表达式
- walrus 运算符（`:=`）
- match-case 语句
- 复杂推导式
- 任何 Python 特有语法

## 2. 选词优化：段落 → 函数

### 2.1 变更内容

| 旧关键词 | 新关键词 | 说明 |
|---------|---------|------|
| `段落` | `函数` | 更直观，初学者一目了然 |
| `段` | `函数` | 单字别名同步更新 |

### 2.2 向后兼容

`段落` 和 `段` 作为别名保留，使用时触发 `DeprecationWarning`：
```
DeprecationWarning: 语法「段落 名 接收 参数」已废弃，
请改用「函数 名(参数)」。在未来的版本中将移除「接收」关键字。
```

### 2.3 示例

**新语法（推荐）**：
```
函数 加法(甲, 乙):
    返回 甲 加 乙。

函数 阶乘(n):
    如果 n 小于等于 1:
        返回 1。
    否则:
        返回 n 乘以 阶乘(n 减 1)。
```

**旧语法（向后兼容）**：
```
段落 加法(甲, 乙):
    返回 甲 加 乙。
```

### 2.4 修饰符同步更新

以下修饰符前缀也使用 `函数`：
- `异步 函数 名():` （原 `异步 段落`）
- `严格 函数 名():` （原 `严格 段落`）
- `松散 函数 名():` （原 `松散 段落`）

## 3. 多异常捕获语法（增强）

### 3.1 新增语法

在原有 `捕获 (TypeA, TypeB)` 括号语法基础上，新增无括号逗号分隔语法：

```
尝试:
    设 甲 为 整数("abc")。
捕获 ValueError, TypeError 错误:
    打印 错误。
```

### 3.2 支持的全部语法形式

| 语法 | 说明 |
|------|------|
| `捕获 错误:` | 无类型，仅变量 |
| `捕获 ValueError:` | 仅类型 |
| `捕获 ValueError 错误:` | 类型 + 变量 |
| `捕获 ValueError, TypeError:` | 多类型（无括号） |
| `捕获 ValueError, TypeError 错误:` | 多类型 + 变量 |
| `捕获 (ValueError, TypeError):` | 多类型（括号，向后兼容） |
| `捕获 (ValueError, TypeError) 错误:` | 多类型 + 变量（括号，向后兼容） |

### 3.3 生成的 Python 代码

```
except (ValueError, TypeError) as 错误:
    print(错误)
```

## 4. 成员访问统一（推迟）

### 4.1 现状

当前存在双重成员访问体系：
- `的` — 用于段言自身对象
- `.` — 用于外部对象（Python import 的对象）

### 4.2 推迟原因

经评估，统一为 `的` 的影响面过大：
- 48 个 .duan 文件使用 `.` 成员访问（1556 行代码）
- import 路径中的 `.`（如 `导入 os.path`）无替代方案
- `TokenType.DOT` 同时承担句号和成员访问两种语义，需先拆分

### 4.3 分阶段计划（未来实施）

1. **Phase 1**：拆分 `TokenType.DOT` 为 `TokenType.PERIOD`（句号）和 `TokenType.DOT`（点号）
2. **Phase 2**：为 import 路径设计替代语法（如 `导入 os/path` 或 `导入 os::path`）
3. **Phase 3**：迁移 48 个 .duan 文件从 `.` 到 `的`
4. **Phase 4**：移除 `.` 成员访问语义

## 5. 迁移工具更新

`tools/migrate_syntax.py` 新增第 4 项迁移规则：

```
段落 名(参数):  →  函数 名(参数):
严格 段落 名():  →  严格 函数 名():
异步 段落 名():  →  异步 函数 名():
```

用法不变：
```bash
python tools/migrate_syntax.py --dry-run stdlib/
python tools/migrate_syntax.py stdlib/
```
